Filtering Event Notifications

When subscribing to event notifications, you can filter which events you want to be notified about using an include list or exclude list.

Server Events

Server events are specific to server on which they are generated. For each server in site there should be one Socket.IO channel opened between the client and ACC Web End Point to get events or configure a webhook to receive site wide events.

Site Events

Site events include events generated by any server in the site. One Socket.IO connection is sufficient to get these events.

For more information on how to integrate these filters with your integration, please use the following links:

  • Event Monitoring with ACC Webhooks
  • Socket.io Notification Channel.
  • Webhooks vs Socket.IO

Getting Events

A list of available events can be obtained using the following rest and socket.io calls. These events are organized into groups so you can request a collection of events at a time.

Rest

https://127.0.0.1:8443/mt/api/rest/v1/event-subtopics

Socket.io

socket.emit(
'read-event-subtopics',
{},
 response => console.log('read-event-subtopics:\n', JSON.stringify(response, undefined, '  '))
);

Including Events

Use the “include” parameter to subscribe to specific events or groups.

To subscribe to specific alarm events, add them to your “include” array.

{
    include: ['ALARM']  // subscribe to ALARM related events
}

Excluding Events

Use the “exclude” parameter to subscribe to all notifications except specific events or groups.

For example, to subscribe to all notifications except storage and database notifications, add STORAGE and DB groups to your exclude array. You can also exclude specific events by adding them to your “exclude” array.

{
    exclude: ['DB', 'STORAGE']  // subscribe to all events except database and storage related events
};
