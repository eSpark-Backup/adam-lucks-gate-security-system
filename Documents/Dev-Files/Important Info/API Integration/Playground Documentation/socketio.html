Subscribing to ACC Notifications

You can subscribe to runtime ACC notifications using socket.io, an open-source event-based communication engine. When you first configure your system, the ACC Server will return a notification package detailing the initial state of the system. After that, you will receive a notification when an alarm, camera, server, or site is modified or removed.

The following notification topics are available:

Hello Start of the initial notification transmission.
Heartbeat Automatic messages to confirm the server is connected to the client. Sent every 10 seconds unless a notification is received.
Slow_Heartbeat Automatic messages to confirm the server is connected to the client. Sent every 3 minutes unless a notification is received.
Alarms List of alarm IDS that have changed state.
Cameras* List of camera IDs that have changed state. Excludes camera link changes.
Cameras_Light* List of camera IDs that have changed state. Excludes camera link changes. DEPRECATED
Servers List of server IDs that have changed state.
Site Site object with the state change included.
Alarm_objects List of modified or removed alarm objects.
Camera_objects* List of modified or removed cameras. Excludes camera link changes.
Camera_objects_Light* List of modified or removed cameras. Excludes camera link changes.
Server_Objects List of modified or removed servers.
Event ACC Server-specific events (not site-wide).
Rule_Action_Client Rule actions that are triggered by an event.
End_of_Catalog End of the initial notification transmission.

To subscribe to alarm and camera notifications, your ACC Server must be licensed.

* A camera link refers to any addition, removal, or change to the logical connection between a camera and a digital i/o, audio i/o, or server-based analytics, available on the ES Analytics Appliance or the AI Appliance.

Configuring Notifications

To configure your system to subscribe to ACC notifications, you need to install the socket.io-client, then add code to begin receiving notifications. In the following examples, node.js is used.

Note: You will need a valid session ID. You can obtain this by logging in to the API playground.

const io = require('socket.io-client');

const ioOptions = {
    autoConnect: false,
    rejectUnauthorized: false // needed when using a self signed cert
};

const apiAddress = 'https://localhost:8443/mt/api/rt/v1';

const socket = io(apiAddress, ioOptions)
    .on('connect', () => console.log('connected'))
    .on('connect_error', error => console.log('connect_error):', error))
    .on('error', error => console.log('error:', error));

console.log('open connection');
socket.open();

// login to get a valid session...
const session = 'session_id';
const topics = ['HELLO', 'HEARTBEAT', 'ALARM_OBJECTS', 'CAMERA_OBJECTS', 'SERVER_OBJECTS', 'SITE', 'END_OF_CATALOG', 'EVENT'];

// The subtopics are only available for 'EVENT' topic
const subtopics = {
  EVENT: {
    // DEPRECATED: The usage of whitelist/blacklist will be deprecated in ACC 8
    // use include to include specific events
    // use exclude to exclude specific events
    include: ['DEVICE']
  }  
};

socket.emit(
    'sub-notification',
    { session, topics, subtopics, getSiteWideEvents: false },
    response => console.log('sub-notification:\n', JSON.stringify(response, undefined, '  '))
);

socket.on('notification', (notification, callback) => {
    console.log('notification:\n', JSON.stringify(notification, undefined, '  '));
    callback(); // invoking callback(false) will stop the notifications
});

When you run the file, the server will return a notification package detailing the initial state of the system. Subsequent notifications will be sent once an event occurs.

getSiteWideEvents

This parameter specifies whether this particular instance of Web Endpoint should send events from every server within the site or just events generated within this particular server.

Setting this parameter to true while connected to multiple Web Endpoint instances in the same site will cause duplicate events to be received.

Setting this parameter to true will be the equivalent of setting all event Types to be site-wide.

The default value of this parameter is false and can be configured through the WebEndpoint.config.yaml file:

eventSubscribe:
  getSiteWideEventsDefault: false

Filtering Event Notifications

When subscribing to event notifications, you can filter which events you want to be notified about using subtopics to include or exclude events. These events differ from the alarm_objects, camera_objects, server_objects and site notifications, which return information about settings.

For more information, regarding obtaining event topics and how to include and exclude topics, please see Filtering ACC Events.

The following example shows how to get a list of events:

socket.emit(
    'read-event-subtopics',
    {},
    response => console.log('read-event-subtopics:\n', JSON.stringify(response, undefined, '  '))
);

The following example shows how to subscribe to events:

const subtopics = {
  EVENT: {
    exclude: ['DB_REINDEX']  // subscribe to all events except 'DB_REINDEX'
    }
};

Important Considerations

The client must acknowledge all server notifications. If the client is down or experiencing an error that prevents it from acknowledging notifications, the server will close the notification channel to prevent a resource leak.

To close the notification channel gracefully, return false in the acknowledge callback().

socket.on('notification', (notification, callback) => {
    console.log('notification:\n', JSON.stringify(notification, undefined, '  '));
    callback(false); 
});

Detecting Failures

If you’re building an application to monitor if the ACC server disconnects, add the following code:

socket
  .on('acc_disconnect', (error) => {
    logger.error('Received ACC disconnect with error: ', error);

    // add application logic to handle ACC disconnection case
    // ...
  });

Unsubscribing from Notifications

You may want to keep the socket connection open but unsubscribe from the notifications, either to reconnect with a new set of topics or terminate the notification channel completely.

Use the unsubscribe event to communicate the notification channel termination without closing the socket connection:

  function unsubscribe(socket, reason){
    socket.emit('unsubscribe', reason);
  }

Notification Parameters

The notification object properties are described below.

Parameter Type Description
siteId string The ACC site ID.
description string A description of the notification.
type string The notification topic.
time string The notification timestamp in UTC.
id string The notification ID.
modified array The site, server, or camera IDs that were modified. For a description of the included parameters, see the API documentation.
removed array The site, server, or camera IDs that were removed. For a description of the included parameters, see the API documentation.
sequence integer The order the notification is displayed in a notification package.
