Event Monitoring with ACC Webhooks

With the ACC Web Endpoint, you can set up webhooks to receive events from the ACC site.

Webhooks is available for HTTP and HTTPS endpoints. HTTPS is recommended as notifications directed to HTTP endpoints will not be encrypted.

This document outlines how to set up webhooks and describes the format of messages received. All examples are in JSON and Javascript.

Only events are available via Webhooks. For more information regarding alarm_objects, camera_objects, server_objects and site notifications, you will need to use the Socket.io Notification Channel.

Before you start

You’ll need the following:

  • The session string generated from the Login Request.
  • A valid url that will receive ACC webhook notifications.
  • A list of eventTopics that you would like to subscribe to.
    • This is the same as socket.io notification subTopics and requires the same whitelist/blacklist format.
    • For more information, see Filtering ACC Events.
  • An authenticationToken to verify event messages are originating from the ACC webhook service.

Generating Authentication Token

With the authenticationToken, you can verify that event messages are originating from the ACC webhook service and not a third party.

The authenticationToken string should be:

  • atleast 16 bytes of secure, randomly generated data
  • Base-64 encoded

For security, we recommend using a unique authenticationToken for each webhook configuration.

Example:

const crypto = require('crypto');
let authenticationToken;
crypto.randomBytes(16, (err, buf) => {
  if (err) throw err;
  console.log(`${buf.length} bytes of random data: ${buf.toString('hex')}`);
  authenticationToken = buff.ToString('base64');
});

Filtering Event Notifications

You can filter which events you want to be notified about using eventTopics parameter to whitelist or blacklist events.

For more information, see Filtering ACC Events.

The following example shows how to subscribe to events:

 "eventTopics": {
    // subscribes to all events except the following
    "blacklist": [
        "DEVICE_MOTION_START",
        "DEVICE_MOTION_STOP"
    ]
 }

General Webhook Configuration Format

{
    "session": "string",
    "webhook": {
        "url": "string",
        "heartbeat": {
            "enable": true,
            "frequencyMs": 30000
        },
        "authenticationToken": "string",
        "eventTopics": {
            // use whitelist to include specific events
            "whitelist": [
                "DEVICE"
            ]
        }
    }
}
Parameter Description
session The session Token generated from the Login Request. (required)
url The URL of the webhook receiving the event notifications. (required)
heartbeat An object that contains heartbeat notification configurations.
enable Specify whether to enable (true) or disable (false) heartbeat notifications. If enabled, unless specified, frequencyMs will be defaulted to 1 hour.
frequencyMs The time interval for sending heartbeat notifications in milliseconds.
authenticationToken The authenticationToken used to secure Webhook notifications. (required)
eventTopics The event topics to receive notifications for. Use whitelist to include event topics and blacklist to exclude event topics. (required)
whitelist An array of all event topics/categories that should be included
blacklist An array of all event topics/categories that should be excluded

Creating a Webhook

Use the POST /webhooks API to create webhook configurations for your ACC site.

A successful response will let you know which settings were accepted or rejected. An error response indicates the request contained validation errors.

Updating a Webhook

Use the PUT /webhooks API to update an existing webhook configuration for your ACC site. You will need the webhook id and the parameters you want to update.

For example, to disable heartbeat notifications, enter the following. This clears the frequencyMs parameter and will require you to reset it when enabling heartbeat notifications.

{
    "session": "string",
    "webhook": {
        "id" : <WEBHOOK_ID>,
        "heartbeat": {
            "enable": false
        }
    }
}

Getting a Webhook

Use the GET /webhooks API to get all webhook configurations for your ACC site or specific webhook configurations using webhook IDs. The response object returns the eventTopics as a list of eventTopics (), not as event groups.

To get all the webhook configurations in your ACC site, use the following GET request using your SESSION_TOKEN.

https://127.0.0.1:8443/mt/api/rest/v1/webhooks?session=<SESSION_TOKEN>

To get specific webhook configurations, use the following GET request using your SESSION_TOKEN and webhook IDs.

https://127.0.0.1:8443/mt/api/rest/v1/webhooks?session=<SESSION_TOKEN>&ids=<WEBHOOK_ID1>&ids=<WEBHOOK_ID2>

Verifying Messages over HTTPS

For webhooks directed to HTTPS endpoints, the webhook notification is presented in JSON format. The notification will contain the authenticationToken within the payload so you can verify the authenticity.

The following example shows how to verify an HTTPS webhook:

function verifyAuthorizationTokenHTTPS(request) {
    return authenticationToken === request.body.authenticationToken;
}

The following example shows how to extract the payload:

function extractPayloadHTTPS(request) {
    return request.body;
}

Verifying Messages over HTTP

For webhooks directed to HTTP endpoints, the webhook notification is presented as a string, with the following headers:

  • Content-Type: plain/text
  • A hash-based message authentication code (HMAC)-encrypted authorization header.

Use the authorization header to verify the authenticity of the message content by recalculating the hash using the binary buffer of the authenticationToken.

function verifyAuthorizationTokenHTTP(request) {
    const authenticationTokenBinary = Buffer.from(authenticationToken, 'base64');

    const authHeader = request.headers.authorization;
    const hmac = crypto.createHmac('sha256', authenticationTokenBinary);
    hmac.update(request.body);
    const hashInBase64 = hmac.digest('base64');

    return hashInBase64 === authHeader;
}

To extract the notification, parse the string payload into JSON. The following Javascript function is an example of how to do so:

function extractPayloadHTTP(request) {
    return JSON.parse(request.body);
}

Webhook Notification Format

The general webhook notification structure will always contain the following information:

Parameter Description
siteId The ACC site ID.
type The webhook notification type. Examples: HELLO, HEARTBEAT, NOTIFICATION.
time The notification timestamp in ISO-8601.

Hello Message

The hello message is denoted by type: 'HELLO' and indicates that a disconnected ACC server has reconnected. It is an indication that some events may have been missed.

 {
    siteId: 'a267ac4e-d926-4177-91ed-e67b05364016',
    type: 'HELLO',
    time: '2019-10-20T19:01:29.022Z'
  }

Heartbeat Message

The heartbeat message is denoted by type: 'HEARTBEAT' and is sent at the configured frequencyMs time interval after the last successful webhook notification. It indicates that the ACC server is connected, although there are no notifications.

 {
    siteId: 'a267ac4e-d926-4177-91ed-e67b05364016',
    type: 'HEARTBEAT',
    time: '2019-10-20T19:01:29.022Z'
  }

Tips and Best Practices

  • Check that all webhook targets are up and running before receiving notifications. The ACC Web Endpoint can have 5 webhook notifications in flight at a time. If 5 or more webhook targets are unavailable, there will be a noticeable delay receiving notifications on available webhook targets due to timeouts.
  • Queue incoming webhook notifications on a webhook target client instead of processing them right away. If notifications are processed right away, the client is likely to hang.
