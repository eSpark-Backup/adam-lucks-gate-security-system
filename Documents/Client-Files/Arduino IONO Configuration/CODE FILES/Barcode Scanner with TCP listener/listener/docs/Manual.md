TCP/IP Listener for Qscan Barcode Readers (with TCP and Relay opts)
======================================================================


### Scanner Setup - at home

Each scanner should be assigned a UNIQUE identification number N. 
As a convention, N equals the autogenerated ID from the site backend database. So, first, add a scaner in the backend and take note of the new "ID" = N
Write that number with a marker on the back of the scanner.
The Server Port Number is calculated using the formula {42000+ceil(N/5)} (=42001 for the first 5 devices)
The scanner Identifier should be "Scanner N"
The numeric Password will be calculated using the formula ((41414+N)*N) - only the first 5 digits.
- connect the scanner to the same router as the laptop
- install IBC TCP/IP Utility Software from http://www.interbar.com/software.htm > "Tcp Utility V4.4"
- run TCP/IP Utility and go to "Program Reader" page
- Get Parameters
- Set parameters as in parameters.png
```
 Server 1&2 Address				18.217.195.71
 Server 1&2 Port Number			42001
 Identifier					Scanner N
 Password					{first 5 digits from ((41414+N)*N)}
 Inactivity Timer			99	
 MODE						TCP Client
 DHCP 						on	
 Password Required			off
 Clinet Send ID				on
 Phy monitor				on
 Keep Alives				on
```
- Reboot



### Router Setup - on site

The router used in the final on-site setup should:
- have DHCP Enabled
- be Connected Continuously to the internet
- reconnect automatically
- reboot daily



### Server Setup

Open firewall ports 42001 -> 42005
Install the `TCP Listener`: unpack this archive `listener.zip` in a temporary folder /tmp
> chmod 0700 /tmp/listener/install/install 
> sudo /tmp/listener/install/install 

This will install the listener in `/opt/listener` as user `listener`, and set file permissions.

The scanners are using server IPv4 address `18.217.195.71`. If this address will ever change, ALL scanners will need to be reconfigured at home using the laptop and IBC TCP/IP Utility Software



### The TCP Listener - on the server

It allows Barcode Scanners that are configured as TCP Clients to connect and maintain a persistent connection. 
It is installed in `/opt/listener` and runs in background. It is started by a cron job as user `listener`. If it crashes, it restarts automatically.
It listens on port 42001 and 42002 and accepts multiple clients. Use max 5 clients (devices) /port to be safe.
The listener will only accept connections from scanners with a valid Identifier "Scanner N" and only one connection per identifier.
The connections are monitored every 2 minutes, so in case of a network error, scanners will be forced to reconnect.



### The TCP Listener - validating barcode data

Edit the listener config file `/opt/listener/conf/listen.conf`
The barcode data sent by the scanners is processed by the function `barcodeReceived`
I includes 3 examples of how you can validate barcodes: 
- by executing another script (slow)
- by connecting to an API endpoint (slower)
- inside the listener (fast - can query mysql data directly if needed)

The best and fastest option is to perform the barcode validation inside the listener bash script, because fetching an API URL is a huge overhead!



### The TCP Listener - sensor events

Edit the listener config file `/opt/listener/conf/listen.conf`
The sensor events are handled by the functions `sensorEventSXX`



### TCP Listener Administration

See a list of connected scanners:
> sudo find '/opt/listener/run/' -type f -printf "%f\n" -nowarn | grep .pid

Disconnect all scanners (they will reconnect in max 3 minutes)
> sudo killall socat
 
See the last data sent by scanner 1
> sudo tail '/opt/listener/log/Scanner1.log'



### Expanding - adding more scanners:

- first 5 scanners Identifier should be "Scanner 1" "Scanner 2" "Scanner 3" "Scanner 4" "Scanner 5"
- first 5 scanners should use port 42001 ;
- the next 5, port 42002 
- the next 5, port 42003 ( + the listener needs to be configured to listen on  42003 )
- the next 5, port 42004 ( + the listener needs to be configured to listen on  42004 )
